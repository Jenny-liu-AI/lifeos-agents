设计思路与价值模块

      

        上方是可点击产品演示；下方说明「为什么这样拆 Agent、解决什么问题、各模块创造什么价值」。
        本页为离线模拟，真实系统为 Python + Streamlit + SQLite + OpenAI 兼容 LLM。
      


      

        

          
问题定义用户痛点 → 产品一句话

          
    
            
  • 痛点 1：计划做不出来，或做完就忘。
    • 
            
  • 痛点 2：执行过程无反馈，偏离了也不知道。
    • 
            
  • 痛点 3：复盘靠感觉，没有数据。
    • 
          

          
产品一句话：用一组分工明确的 AI Agent，把「目标 → 计划 → 执行 → 反馈 → 修正」闭环自动化；人只打卡和做决策，不自己维护表格与复盘文档。

          

            目标→
            计划→
            执行打卡→
            反馈数据→
            修正（周复盘）
          

        


        

          
设计思路为什么用多 Agent，而不是一个大 Prompt

          
    
            
  • 职责分离：路由决策、任务拆解、学习辅导、生活节律、周期复盘的目标函数不同；塞进一个 Prompt 易互相干扰、难兜底。
    • 
            
  • 可观测：每次调用写入 Agent 日志（输入/输出摘要、耗时、token、成败），调试与排障都能对上「谁做错了」。
    • 
            
  • 可降级：每个 Agent 有独立 JSON schema + 解析重试 + 中文兜底；API 挂了页面不白屏，仍可手动加任务。
    • 
            
  • 交付约束：个人自用、24 小时可跑通；Streamlit 单页 + SQLite，不做登录/RAG/分布式调度。
    • 
          

          
多 Agent 的价值不在「Agent 数量」，而在边界清晰 + 失败可隔离 + 过程可审计。

        


        

          
架构三段式：主控路由 + 专职执行 + 周期校验

          
    
            
  • 主控路由（Orchestrator）：看目标与近 7 天完成率，决定今日 plan_mode、调用谁、聚焦哪些目标。
    • 
            
  • 专职执行（并行）：Planner 出任务；Coach 出学习结构；Life 出作息/运动建议。用线程池并行，缩短等待。
    • 
            
  • 周期校验（Reviewer）：周维度触发，强制引用完成率等数字作 evidence，避免空泛鸡汤。
    • 
          

          
Orchestrator 不写具体任务，避免「自己定方向又自己写计划」的自我合理化；Reviewer 不掺进每日生成，避免边计划边美化结果。

        


        

          
价值模块目标管理

          
管理学习 / 健康 / 其他长期目标：名称、描述、截止日、每周投入小时、归档。

          
    
            
  • 完成率进度条来自任务真实状态，而非手填百分比。
    • 
            
  • 价值：把「模糊愿望」变成系统可调度的对象。
    • 
          

        


        

          
价值模块每日计划生成

          
一键生成当日可执行清单（每目标 1–3 条，含时长与优先级），可手动增删改。

          
    
            
  • 硬约束：单日 ≤6 条、单任务 ≤90 分钟、总时长不超过可用时长。
    • 
            
  • 价值：解决「计划做不出来 / 做完就忘」——每天打开即有下一步。
    • 
          

        


        

          
价值模块打卡与执行反馈

          
对任务标记完成 / 部分完成 / 未完成，可写备注与实际分钟。

          
    
            
  • 写入 checkins 并同步任务状态，复盘与目标进度共用同一数据源。
    • 
            
  • 价值：执行过程可见，偏离能被数据看见，而不是靠自觉。
    • 
          

        


        

          
价值模块周复盘纠偏

          
基于本周计划 vs 完成情况生成报告：完成率、亮点、问题（含 evidence）、下周调整。

          
    
            
  • 约束：problems 必须带证据字段，引用具体数字。
    • 
            
  • 价值：把「感觉复盘」升级为「数据复盘 + 可执行调整」。
    • 
          

        


        

          
价值模块Agent 可观测面板

          
每次 Agent 调用留痕：名称、输入/输出摘要、耗时、token 估算、成功/失败。

          
    
            
  • 这是「平台感」的关键：能证明系统在协作，而不是黑盒一次生成。
    • 
            
  • 价值：便于调试，并清晰展示多 Agent 协作链路。
    • 
          

        


        

          
五个 Agent各agent职责速查

          
    
            
  • Orchestrator：今天干什么、叫谁 —— 路由与节奏（normal / catch_up / light）。
    • 
            
  • Planner：把目标拆成今天能做完的具体任务。
    • 
            
  • Coach：学习类任务的材料结构与自测题。
    • 
            
  • Life：健康/作息建议，并给「天气不佳」的常识替代方案（不接天气 API）。
    • 
            
  • Reviewer：周报级校验，必须引用数据。
    • 
          

          

            技术栈选型：Streamlit 降低前端成本；SQLite 零运维；LLM 统一走 llm.py（chat / chat_json + 重试）；
            调度用「每日首次打开自动触发 + 手动按钮」，刻意不做分布式，匹配个人自用场景。
